REST contract of the linehaul-transportation bounded context of the retail network, derived from retail-network-docs apis/linehaul-transportation/openapi.yaml and model/model.yaml (contexts[linehaul-transportation].rest), adjusted by the Model Gap Register decisions G3, G9, G14, G15, G28 and G29 and by the cross-context decisions E3, E13, E14 and E16 (ADR 0002). The service runs the middle mile: it turns lane schedules and the declared cutoffs of vendor nodes into scheduled departures, keeps each departure's remaining capacity, builds loads of packages onto departures and reports when loads depart and arrive. The planner calls the lane-schedule routes, the departure cancel and change-capacity routes; sort-centre and station operators call the load routes; any context may call the departure reads. Domain events are published on Kafka (apis/asyncapi.yaml), never over REST. No authentication, consistent with the fleet. Errors are RFC 9457 problem details; the shared problem types are not-found (404), illegal-transition (409), concurrent-update (409) and validation-failed (422), plus one type per model Err name. Every state-changing POST takes a required Idempotency-Key.
